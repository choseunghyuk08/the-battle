# game-text-ko — 게임 한국어 텍스트 작성 규칙

사람이 쓴 것처럼 읽히는 게임 텍스트를 쓰기 위한 작성 규칙. 다 쓴 글을 고치는 윤문기가 아니라, **쓰기 전에 결정하고 쓰면서 지키는 규칙**이다.

## 0. 시작 절차 — 쓰기 전에 네 가지를 정한다

텍스트를 한 줄이라도 쓰기 전에 아래 순서로 판별한다. 판별 근거는 프로젝트의 CLAUDE.md, 기획 문서, README, 기존 대사·텍스트 파일, 에셋 이름, 사용자의 요청 문장이다. **근거가 없어서 못 정하면 사용자에게 한 번 묻는다** (장르와 배경만 짧게). 추측으로 밀고 가지 않는다.

| 순서 | 정할 것 | 선택지 | 그 다음 읽을 파일 |
|---|---|---|---|
| 1 | **텍스트 종류** | 캐릭터 대사 / 선택지 / 독백·내레이션 / 발견 텍스트 / 튜토리얼 / 아이템·스킬 설명 / 시스템 메시지·버튼·알림 / 짧은 반복 대사(barks) | §2 결정표 → `references/text-types.md` |
| 2 | **장르(톤)** | 공포 / 판타지 RPG / 캐주얼·방치형·힐링 / SF·사이버펑크 / 일상·감성·내러티브 / 혼합 | §4 라우팅 → `references/genre-*.md` 중 해당 파일 |
| 3 | **배경(시대·세계)** | 조선·전근대 한국 / 중세 서양풍 / 현대 / 근미래 / 가상 세계 | 조선·전근대 한국이면 `references/setting-joseon.md`. 그 외는 장르 파일의 어휘 지침 |
| 4 | **화자의 역할** | 상인 / 의뢰인 / 동료 / 악역 / 신·초월자 / 안내자 / 군중 / 아이·노인 / 비인간(AI·기계·유령) / 시스템(목소리 없음) | §3 요약 → `references/roles.md` |

장르와 배경은 따로 정한다. "조선 배경인데 캐주얼"(예: 행사용 귀신 잡기 게임)과 "현대 배경인데 공포"가 모두 가능하다. 장르가 톤을, 배경이 어휘를 정한다.

이미 쓰인 텍스트가 프로젝트에 있으면 **그 텍스트의 어미·호칭·말버릇을 먼저 읽고 맞춘다.** 새 톤을 들고 오지 않는다.

## 1. 공통 규칙 10개 (장르 불문)

1. **대사는 문장이 아니라 소리다.** 조사·주어를 빼고, 어순을 뒤집고, 중간에 끊어라. 소리 내 읽어서 낭독문처럼 들리면 실패. "나는 그 고개를 넘지 않을 것이오" → "안 넘소, 그 고개는."
2. **감정을 이름으로 말하지 않는다.** "무서워", "화났어", "고마워", "슬프다" 금지. 행동·딴소리·사물로 바꾼다. "나는 지금 매우 두렵다" → "…불 좀 더 지펴. 손이 왜 이러지."
3. **설명하지 않는다.** 인물은 자기가 사는 세계를 남에게 해설하지 않는다. 세계관·역사·시스템은 코덱스와 UI로, 대사는 태도와 관계만. 반만 말하고 말을 돌린다.
4. **정보는 고정, 태도만 바꾼다.** 같은 "북쪽 다리 건너 두 번째 골목" 안내도 화자가 무엇을 신경 쓰는지(경고, 수치, 감나무, 침묵)에 따라 전혀 다른 대사가 된다. 캐릭터성은 정보 옆에 붙은 태도에서 나온다.
5. **앞 대사가 뒷 대사를 바꿔야 한다.** 준비된 문장을 교대로 읽는 대화 금지. 상대 말에 걸려 넘어지고, 되묻고, 끊는다. 한 화자가 연속으로 말하는 구조면 턴 사이에 짧은 지문 1줄(행동·플레이어의 시선)을 넣고, 그 지문에 다음 턴이 반응하게 한다.
6. **문장 길이에 낙차를 둔다.** 한 줄짜리와 세 줄짜리를 섞는다. 전부 12~15자 단문이면 AI 문체다.
7. **인물마다 어미·호칭·말버릇을 고정하고 서로 다르게.** 화자 이름을 가리고 읽어서 누구인지 못 맞히면 다시 쓴다. 말버릇은 캐릭터당 1개. 하오체·고어체처럼 튀는 어미는 NPC 전체 중 1~3명에만 (플레이어 캐릭터의 어미는 이 수에 넣지 않는다 — 플레이어 어미는 게임이 정한 기본값을 따른다).
8. **같은 장치를 한 장면에 두 번 쓰지 않는다.** 말줄임표, 침묵, 숫자 세기, 반복, 4의 벽 농담 — 두 번째부터 독자는 패턴을 읽는다.
9. **마지막 줄에서 결론·교훈·정리를 뺀다.** 대화는 끊기거나 딴 데로 새며 끝난다. "결국 중요한 건 서로를 믿는 거야" 류 금지.
10. **첫 글자부터 발화다.** "물론입니다, 다음은…" 같은 채팅 서두, 괄호 해설, 작가의 설명 문장을 게임 텍스트에 남기지 않는다.

상세 기법(구어체 변환표, 서브텍스트, 말풍선·웹소설 리듬)은 `references/common-rules.md`.

## 2. 텍스트 종류별 결정표

| 종류 | 기본 어미 | 길이 | 핵심 규칙 | 금지 |
|---|---|---|---|---|
| 캐릭터 대사 | 캐릭터별 고정 (반말/해요/합쇼/하오 중 1) | 말풍선 1개 = 20~30자, 최대 2문장. 한 턴 2줄 | 질문에 늘 대답하지 않는다. 미완결 문장 최소 1개 | 설명조, 설정에 없는 어미, 감정 명사 |
| 선택지 | 플레이어 캐릭터 말투 | 5~10단어 | 선택지끼리 **태도**가 달라야 한다(협박/설득/농담/침묵). 문구와 실제 발화가 어긋나지 않게 | "도와준다/거절한다", "정보를 더 요청한다" 같은 UI체 |
| 독백·내레이션 | 1인칭 또는 3인칭, 문어 허용 | 마침표마다 줄바꿈 | 보는 사람이 있다 — 늦게 알아채고, 잘못 보고, 부정한다. 숫자·감각·행동만 | 형용사로 분위기 말하기, "~다." 균일 반복 |
| 발견 텍스트 (쪽지·일기·장부·낙서·로그) | 글쓴이 신분에 맞게 | 한 장 = 한 사실 | 형식을 진짜처럼(장부는 장부답게). 첫 줄은 평범. **쓴 사람의 목적**(경고·광고·울분)이 있다. 독자는 플레이어가 아니라 세계 속 누군가 | 줄거리 요약을 낙서로 적기, "이 글을 읽는 자여" |
| 튜토리얼 | 해요체 + 명령형 | 1문장 1행동, 25자 내 | UI 요소명은 화면 표기와 글자까지 동일. 호칭은 첫 등장 1회 | 두 행동 묶기, 조건문, 과잉 공손 |
| 아이템·스킬 설명 | 효과 = 명사형/합니다체 · 플레이버 = 별도 줄, 평서 문어체 | 효과 1줄 + 플레이버 1~3문장 | 플레이버는 ①정체 ②기능과 연결된 설화 ③빈칸 남기는 마지막 문장. 다음 질문을 낳게 | 효과와 감성 문장 섞기, 설화를 결말까지 적기 |
| 시스템 메시지·토스트 | 명사형 또는 "~했어요/~됐어요" (게임 톤 따라) | 쿨·기본 톤 15자 1문장 / 힐링·유머 톤은 2문장 25자까지 허용 | 에러는 "무엇을 하면 되는지" 포함 | "~하여 주시기 바랍니다", 사과 2회, 피동 남발("지급되었습니다") |
| 버튼·메뉴 | 명사형 / "~하기" | 2~6자 | 단일 CTA "~하기", 전환 "확인/다음", 부정은 "닫기/다음에" | 문장형, "예/아니오" |
| 푸시 알림·공지 | 알림 = 해요체(캐릭터 1인칭 가능) · 공지 = 합니다체(운영자) | 제목 15~20자 | 플레이어 호칭은 IP당 1개로 전 텍스트 고정 | 캐릭터 말투가 공지에 침입, 매번 같은 문구 |
| 짧은 반복 대사 (barks: 피격·승리·상점 입장·대기) | 캐릭터 어미 | 2~6단어 | 트리거당 5~10개 변주. 정보 1 + 성격 1. 변주 간 어휘 겹침 최소. 상태 변수(무기·사망 횟수·시간대)를 바꾸는 변주가 동의어 치환보다 낫다. 말버릇은 변주 5개 중 1~2개에만 붙인다(어휘 겹침 회피가 우선) | 플레이어를 부끄럽게 하기, "다시 왔군/또 왔군" 식 동의어 변주 |

상세와 예문은 `references/text-types.md`.

## 3. 역할별 목소리 요약

어미는 **마지막에** 정한다. 순서: ①역할의 욕망과 정보량 → ②장르가 정하는 세계관 신뢰도(불신/낙관/메타 자각) → ③상태 변수 변주 → ④그제서야 어미·문장 길이.

| 역할 | 문장 길이 | 정보량 | 자주 하는 행동 | 핵심 |
|---|---|---|---|---|
| 상인 | 짧음 | 상품·가격 | 흥정, 손님 평가, 재방문 인사 | "팔고 싶은 욕망"이 문장마다 보인다 |
| 퀘스트 의뢰인 | 중간 | 높지만 **한 번에 다 안 줌** | 떠보기, 숨기기, 조건 붙이기 | 정보보다 감정 상태(패닉·체념·의심)를 먼저 |
| 동료 | 짧고 잦음 | 의견·판단 | 찬반, 기억·앙심, 잡담 | 설명이 아니라 **입장 표명**. 플롯 요약은 플레이어 몫 |
| 악역 | 길어도 됨 | 가치관 | 플레이어를 '이해'한다고 주장, 선택 재해석 | 자기 논리에서 옳다 |
| 신·초월자 | 극단적(아주 짧거나 아주 긺) | 의도적 생략 | 시간 감각 왜곡, 인간사 사소화, 거래 | 질문에 **직접 답하지 않는다** |
| 안내자(튜토리얼 역) | 짧음, 명령형 1개 | 기능 정보 | 시범, 칭찬, 실수 유머화 | 기능 설명을 캐릭터 욕망에 포장 |
| 군중·잡담 NPC | 1문장 | 거의 0 | 날씨·소문·불평 | 월드 상태(전쟁·역병·세금)를 간접 반영 |
| 아이 | 짧음, 존칭 서툼 | 보이는 것 그대로 | 어른이 안 보는 것을 말함 | 가장 무서운/웃긴 진실을 아무렇게나 |
| 노인 | 중간, 격언 인용 | 과거 | 금기 전달, 세 번 말하기 | 결말을 안 맺는다 |
| 비인간(AI·기계·외계·유령) | 역할 따라 | — | 사회 규칙 **한 가지**를 일관되게 틀림 | 문법은 맞고 감각 하나만 어긋나야 '다른 존재'로 읽힌다. 무작위로 어색하면 번역 오류로 읽힘 |

역할별 상세(컨셉별 상인 3종, 동료 호감도 단계, 비인간 설계, 10대·20대 말투)는 `references/roles.md`.

## 4. 장르 라우팅

장르를 정했으면 해당 파일 **하나만** 읽는다. 혼합이면 주 장르 파일 + 부 장르 파일의 "핵심 5줄"만.

| 장르 | 파일 | 한 줄 요약 |
|---|---|---|
| 공포 | `references/genre-horror.md` | 보여주지 말고 담담하게. 인물은 무서움을 피한다. 발견 텍스트는 뒤로 갈수록 무너진다 |
| 판타지 RPG (다크/밝은/블랙코미디) | `references/genre-fantasy-rpg.md` | 역할 × 세계관 신뢰도. 아이템 설명은 빈칸을 남긴다. 하오체는 소수 캐릭터에만 |
| 캐주얼·방치형·힐링·모바일 | `references/genre-casual-idle.md` | 말버릇 1개, 종류별 어미 고정, 톤 섞임 금지. 플레이어 호칭 1개 |
| SF·사이버펑크 | `references/genre-scifi.md` | 계급은 문장 길이와 공손함의 격차로. 비인간은 톤과 내용의 불일치 |
| 일상·감성·내러티브 | `references/genre-slice-of-life.md` | 플롯과 무관한 디테일 1개 + 미완결 1개. 세대감은 유행어 아닌 문장 구조 |
| 배경이 조선·전근대 한국 | `references/setting-joseon.md` | 신분별 어미표, 무당 공수, 귀신을 직접 안 부르는 완곡어, 굿·무구·시간·장소 어휘 |

## 5. 제출 전 AI 티 체크리스트 (20개)

쓴 텍스트를 전부 걸어 본다. 하나라도 걸리면 고친다. 상세 원인과 교정 예는 `references/ai-failure-patterns.md`.

**문장**
1. 모든 문장이 완결형("~다/~요"로 끝남, 조사·주어 다 있음) → 최소 하나는 끊거나 뒤집어라
2. 문장 길이 균일 → 낙차
3. "A하고, B하고, C했다" 3개 묶기 / "~뿐만 아니라 ~도" → 지워라
4. "단순한 X가 아니다, Y다" 부정 대구 → 지워라
5. 접속사·연결어("하지만", "그럼에도", "결론적으로") 대사 안에 → 지워라
6. 줄표·말줄임표가 한 장면에 3개 이상 → 하나만
7. 부사가 기계적으로 문두("천천히 그는") → 어순 바꿔라
8. 맞춤법이 교열본처럼 완벽 → 구어엔 "됐구먼", "그니까" 같은 흐트러짐 허용
9. 번역투("~에 의해", "~을 가지고 있다", "~것 중 하나", 불필요한 "-들", 피동 남발) → 능동 구어로

**대사**
10. 감정을 이름으로 말함 → 행동·딴소리로
11. 인물이 이미 아는 정보를 서로에게 말함(세계관 해설) → 반만 말하고 돌려라
12. 앞 대사가 뒷 대사를 바꾸지 못함(교대 낭독) → 걸려 넘어지게
13. 모든 인물이 같은 말투 → 역할표로 갈라라
14. 모든 NPC가 플레이어를 존중하고 질문에 성실히 답함 → 산적은 산적처럼, 거절하면 NPC도 식는다
15. 끝에 교훈·정리 한 줄 → 지워라
16. 같은 장치가 한 장면에 두 번 이상 → 하나만
17. 유행어·속어가 한 문장에 2개 이상 → 캐릭터당 1개, 씬당 1회
18. "~하시겠습니까?", "~하여 주시기 바랍니다" 과잉 공손 → 게임 톤의 어미로
19. 느낌표 2개 이상, 이모지(UI 밖) → 한 신에 느낌표 하나
20. 채팅 서두("물론입니다", "다음은"), 괄호 해설, 작가 설명 잔존 → 삭제

## 6. 작업 절차

1. §0으로 종류·장르·배경·역할을 정한다. 근거 없으면 사용자에게 묻는다.
2. 해당 reference 파일을 읽는다 (장르 1개 + 필요시 배경 + 역할/종류).
3. 화자마다 **어미 1개, 호칭 1개, 말버릇 1개, 절대 하지 않는 말 1개**를 적어 둔다. 기존 텍스트가 있으면 거기서 뽑는다.
4. 화자가 **무엇을 숨기는지** 정한다. 직접 말하지 않을 것 하나.
5. 초고를 쓴다. 감정 단어를 써도 된다.
6. 퇴고: 감정 단어 삭제 → 조사·주어 삭제 → 한 문장 끊기 → 괄호 해설 삭제 → 마지막 줄 결론 삭제 → 글자 수 확인.
7. 소리 내 읽는다(혀가 걸리면 자른다). 화자 이름 가리고 읽는다(누군지 모르면 3번으로).
8. §5 체크리스트 20개.
9. 반복 대사는 연속 10회 재생을 상상하고 짜증 나면 변주를 추가한다.
10. 사용자에게 보여줄 때는 결과 텍스트만. 규칙 설명을 덧붙이지 않는다.
