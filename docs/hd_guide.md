# HD 적 그림 작업 안내

적 110종을 **고해상도(HD)로 직접 새로 그린다**. 기존 그림은 48x36 도트 칸에 그린 것을 2배로 키운 것이라 도트 한 칸이 화면 2칸이다. HD 그림은 처음부터 실제 해상도(점 한 칸 = 화면 반 칸)로 그려서, 같은 크기에서 점이 4배 많다. 그 점들로 눈, 이빨, 털, 주름, 광택, 흠집을 직접 그린다.

도구는 `js/hd.js`, 예시는 `js/hd_examples.js` (쥐 = 네발 짐승, 좀비 = 사람꼴). 먼저 둘 다 읽는다.

## 좌표와 크기

- 단위는 **점**이다. 화면 1px = 2점 (`h.u` = 2). 그림은 코드 안에서 점 단위로 직접 그린다.
- `x`: 0이 발밑 가운데, **오른쪽이 앞**이다. 적은 화면에서 왼쪽을 보도록 자동으로 뒤집혀 나온다. 그림은 항상 오른쪽을 보게 그린다.
- `y`: 0이 땅이고 **위쪽이 음수**다. 머리 꼭대기가 -70이면 70점 높이다.
- **화면 크기는 정해져 있다.** `YG.SIZES.enemyPx(def)` 가 화면 px 단위의 긴 쪽 크기다 (그림에서 가로가 세로 이상이면 가로, 아니면 세로. 몸통 + 꼬리 + 수염처럼 그림 전체 바깥 상자 기준). 점으로는 그 값 x 2. 이 크기에 ±8%(최소 2px) 안으로 맞춰 그린다. `fit`/`scale` 은 HD 그림에 적용되지 않는다.
  - 예: 쥐 약 22px = 44점 가로, 좀비 35px = 70점 세로, 보스는 65~85px = 130~170점.
  - 작은 적은 점이 적다. 그 안에서 가장 중요한 특징(눈, 이빨, 상징)을 먼저 살린다.
- 기존 그림이 하던 것(모양, 색, 상징, 소품)은 그대로 이어받는다. 새 디자인이 아니라 **같은 적을 더 정교하게 다시 그린 것**이다. 기존 그림은 HD를 등록하기 전에 `node tests/strips.js e:<id> 6 old` 로 볼 수 있다. 색은 `def.look` (객체이거나 문자열)과 `js/bestiary*.js`에 있다. 도감 이야기(`js/lore*.js`)도 읽고 분위기를 맞춘다.

## 도구 (h)

`YG.HD.<id> = (h, q, def) => { ... }`. id는 색 변종을 뗀 원래 id다 (`rat:red` 도 `rat` 를 쓴다). 순수 함수여야 한다 (`Math.random` 금지. 깜빡임은 `q.n`, `q.ph` 로).

| 호출 | 설명 |
|---|---|
| `h.r(x, y, w, hh, color)` | 사각형. 왼쪽 위가 (x, y) |
| `h.px(x, y, color)` | 점 하나 |
| `h.line(x0, y0, x1, y1, color, 두께=1)` | 선 |
| `h.ell(cx, cy, rx, ry, color)` / `h.disc(cx, cy, r, color)` | 채운 타원 / 원 |
| `h.poly([[x, y], ...], color)` | 채운 다각형 |
| `h.layer(() => {...}, 외곽선색?)` | 안에서 그린 것을 한 덩어리로 묶어서 **한 점 외곽선**을 두른다. 팔, 다리, 머리, 소품처럼 따로 윤곽이 필요한 것에 쓴다. 덩어리끼리는 그린 순서대로 앞뒤로 쌓인다 |
| `h.spark(x, y, w, hh, color)` | 외곽선 밖에 맨 위로 얹는 것 (수염, 빛, 반짝임, 연기, 눈물). 외곽선이 안 생긴다 |
| `h.rim(color)` | 맨 바깥 외곽선 색을 바꾼다 (그림자 같은 아주 어두운 적. 기본 `#141218`) |
| `h.tone(color, amt)` | 색을 밝게(+) / 어둡게(-) (-1..1) |
| `h.mix(a, b, t)` | 두 색 섞기 |

- `layer` 밖에서 그린 것은 맨 바깥에만 자동 외곽선이 생긴다.
- 색은 `#rrggbb` 만 쓴다 (밝고 어두운 변형은 `h.tone` 이 만든다). 반투명 색은 `h.spark` 에서만 `rgba(...)` 를 쓴다.
- 부분이 너무 많으면 느려진다. 한 프레임에 사각형 수천 개까지는 괜찮지만, `ell`/`poly` 가 한 줄씩 쪼개서 내는 것도 센다. 큰 보스는 `h.r` 로 큰 면을 먼저 칠하고 디테일을 올린다.

## 자세 값 (q)

프레임은 56장이다: `idle` 12, `walk` 16, `atk` 24, `hurt` 4. `q.kind` 로 구분하고, 값은 전부 **논리 px(점 2개) 단위의 소수**다. 점으로 쓰려면 `h.u` 를 곱한다.

| 값 | 뜻 |
|---|---|
| `q.kind` | `'idle'`, `'walk'`, `'atk'`, `'hurt'` |
| `q.n` | 그 동작 안에서 몇 번째 장 (idle 0..11, walk 0..15, atk 0..23, hurt 0..3) |
| `q.ph` | 동작 한 바퀴 중 위치 0..1. 숨쉬기, 꼬리 흔들기, 다리 사이클에 `Math.sin(q.ph * 2π)` 로 쓴다. 공격은 처음~끝 |
| `q.bob` | 몸이 위로 떠오른 정도 (걷기 0..1, 숨쉬기 0..1) |
| `q.step` | 걸을 때 앞뒤로 벌어진 정도 -1..1 (`cos(2π·ph)`) |
| `q.wind` | 공격 준비로 뒤로 당긴 정도 0..1 |
| `q.atk` | 공격이 뻗은 정도 0..1 (맞는 순간이 1) |
| `q.lunge` | 몸이 앞뒤로 쏠린 정도 (-4..4) |
| `q.rise` | 몸이 뛰어오른 정도 |
| `q.hurt` | 맞은 상태 (표정을 찡그리고 몸을 뒤로) |

- **공격 24장**: 0~13이 준비(뒤로 당김, 잠깐 버팀, 휘두르기 시작), 14~17이 맞는 순간(가장 뻗음은 15), 18~23이 되돌아옴이다. `q.wind`/`q.atk` 가 이 흐름을 곡선으로 준다. 준비가 눈에 보이게, 맞는 순간이 세게, 돌아옴이 부드럽게 보이도록 몸 전체(몸통 기울기, 머리, 팔다리, 꼬리, 입)를 같이 움직인다.
- **걷기**: 두 걸음이 한 바퀴다. 다리와 팔을 `q.ph` 로 엇갈리게 움직이고 몸은 `q.bob` 으로 위아래로 흔든다. 떠다니는 적은 위아래로 넘실댄다.
- **서 있기**: 숨 쉬는 움직임 + 눈에 띄는 작은 움직임 (꼬리, 눈 깜빡, 털 흔들림, 김, 깜빡이는 불빛 등).
- **맞기**: 표정과 몸이 찡그려지고 뒤로 젖혀진다.
- 공중에 떠 있는 적(`def.float`)은 몸을 땅(y=0)에서 띄워서 그리고 `q.bob` 으로 넘실댄다. 그림자는 화면이 따로 그린다.
- 원거리 적(`def.ranged`)의 투사체는 화면이 `def.ht` 절반 높이에서 쏜다. 그 높이쯤에 입, 눈, 총구 같은 발사 지점이 오게 그린다.

## 그림 품질 기준

1. 색은 한 부분당 **3~4톤**(밝은 곳, 기본, 그늘, 가장 어두운 곳)으로 칠한다. 빛은 왼쪽 위에서 온다. 기본색은 기존 그림에서 가져오고 `h.tone` 으로 만든다.
2. 눈에는 반드시 눈동자와 흰 반짝임 한 점. 입, 이빨, 발톱, 손가락 같은 작은 특징을 그린다.
3. 질감: 털(짧은 결), 비늘, 나무결, 금속 패널과 나사, 천 주름, 피부 결을 점으로 암시한다. 같은 무늬를 격자로 찍지 말고 크기와 위치를 흩뜨린다 (`q` 에 무관한 위치는 고정값이어야 프레임 사이에 깜빡이지 않는다).
4. 실루엣이 한눈에 보여야 한다. 작은 점(1~2점)은 눈, 반짝임, 이빨 정도에만 쓰고 큰 형태가 먼저 읽히게 한다.
5. 한 적의 56프레임이 서로 어긋나지 않게 한다 (프레임마다 몸 크기와 비율이 일정). 발끝이 `y=0` 에 닿는다.
6. 색 변종이 기본 그림 위에 반투명 색을 덮는다. 너무 어둡거나 너무 밝은 한 가지 색으로만 칠하지 않는다.

## 확인 방법

```
node tests/spritecheck.js id,id       # 56프레임이 전부 그려지는지 (예외, 빈 그림)
node tests/sizecheck.js               # 화면 크기가 맞는지. 내 id 가 목록에 있으면 맞춘다
node tests/strips.js e:id,e:id 6 name atk   # 프레임을 한 줄로 늘어놓은 그림 -> tests/out/name.png (줄: idle,walk,atk,hurt 중 고르기)
node tests/sim.js                     # 전체 테스트. 커밋 전에 통과해야 한다
```

- 그림은 `Read` 도구로 `tests/out/name.png` 를 열어서 눈으로 확인한다. 배율 6~8로 몇 프레임만 크게 보고, 마지막에 56프레임 전체도 한 번 훑는다 (프레임 사이가 뚝뚝 끊기지 않는지, 이상하게 튀는 프레임이 없는지).
- `tests/out/` 은 git 에 올라가지 않는다.
- `js/sizes.js`, `js/hd.js`, `js/hd_examples.js`, `tests/` 와 다른 `js/hd_*.js` 는 고치지 않는다. 내 파일만 쓴다. 도구에 모자란 게 있으면 내 파일 안에 도우미 함수를 만들어 쓴다.
