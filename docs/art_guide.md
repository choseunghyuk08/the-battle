# 그림 작업 안내 (뭐든 던져)

게임: 폰 세로 화면. 위쪽 전투 화면에서 주인공(왼쪽)이 보드의 물건을 던지고, 몬스터가 오른쪽에서 걸어온다. 아래쪽 보드에서 같은 물건 2개를 합치면 다음 단계 물건이 된다. 모든 그래픽은 픽셀 아트 스프라이트다.

**모든 그림은 코드로 그린다.** `js/sprite.js` 의 그리기 도구(`b`)로 자세 값에 따라 도형을 그려서 프레임을 여러 장 뽑는다. 사용자가 가장 신경 쓰는 것은 **많은 프레임으로 자연스럽게 움직이는 것**이다.

## 먼저 읽을 것

1. `js/sprite.js` 맨 위 설명과 `builder` 의 도구들 (`ell disc rect rrect poly line px part save/restore/translate/rotate/scale tone mix`), `TG.anim` 의 움직임 도우미 (`track ease chain lerp clamp TAU`)
2. `js/spr_hero.js` (주인공: 관절 각도로 그리는 사람 예시, 잔상, 부품마다 외곽선)
3. `js/spr_mob_slime.js` (몬스터 예시: 몸 전체를 늘이고 줄여서 통통 튀는 움직임)

## 좌표와 크기

- 단위는 점(dot). 점 하나 = 전투 화면 논리 픽셀 하나. 전투 화면은 200 x 120점이고 땅은 y = 100 이다.
- 그림 칸 `w x h`, 기준점 `ax, ay` (발밑 가운데, 칸 안 좌표). y 는 아래로 갈수록 커진다.
- 주인공 키는 약 34점이다. 보통 몬스터는 16~26점 높이로 그린다 (주인공보다 작거나 비슷하게).
- 거대 몬스터는 같은 그림을 배율 `S = 2` 로 다시 그린 것이다 (도구가 알아서 좌표를 2배로 늘려서 더 정밀하게 그린다). 그러니 **배율 2에서도 예뻐야 한다.** 그릴 때 좌표는 늘 배율 1 기준으로 쓴다.
- 칸 가장자리에 그림이 닿으면 안 된다. 움직이는 모든 프레임이 칸 안에 들어오게 칸을 넉넉히 잡는다 (`node tests/spritecheck.js` 가 잡아 준다).

## 그림 기준

1. 외곽선은 도구가 1점으로 자동으로 둘러 준다 (`#17121e`). 팔다리, 날개처럼 몸과 겹치는 조각은 `b.part(() => {...}, true)` 로 묶어 따로 외곽선을 준다.
2. 빛은 왼쪽 위에서 온다. 도형마다 밝은 가장자리와 어두운 가장자리가 자동으로 생긴다 (`{ shade: false }` 로 끈다). 여기에 직접 무늬, 광택 점, 그늘 덩어리를 더해서 한 부분에 3~4톤을 만든다.
3. 눈, 반짝임 같은 작은 디테일은 `b.px` 로 찍는다. 귀엽고 개성 있는 얼굴이 중요하다.
4. 색은 `palettes` 에서 가져온다. 색 묶음을 여러 개 만들어 테마/강한 개체 변종으로 쓴다.

## 움직임 기준 (가장 중요)

- **반복 동작**(idle, walk, 비행)은 `ph = i / n` 으로 그려서 마지막 장 다음에 첫 장이 매끄럽게 이어지게 한다.
- **한 번 하는 동작**(attack, hurt, die)은 `pr = i / (n - 1)` 로 0에서 1까지 간다.
- 애니메이션 원칙을 쓴다: 예비 동작(공격 전에 뒤로 움찔), 늘이고 줄이기(착지할 때 납작, 뛸 때 길쭉), 따라오는 움직임(귀, 꼬리, 날개, 더듬이가 몸보다 한 박자 늦게 흔들림), 무게감(무거운 것은 느리게 큰 반동).
- 프레임 수는 아래 최소 수보다 많아도 된다. 걷기는 8~12장이 좋다.
- 프레임마다 몸이 튀거나 부품이 떨어져 나가면 안 된다. 연속으로 보면서 확인한다.

## 담당별 할 일

각자 **자기 파일 하나만** 고친다. 파일은 이미 빈 틀로 만들어져 있고 `index.html` 에도 등록돼 있다. `js/sprite.js`, `js/spr_hero.js`, `js/spr_mob_slime.js`, `tests/`, 다른 사람 파일은 고치지 않는다 (도구가 모자라면 자기 파일 안에 도우미 함수를 만든다). 도구에서 이상한 점을 보면 고치지 말고 보고에 적는다.

### 몬스터 (A~F): `js/spr_mob_<테마>.js` 에 3종씩

```js
TG.SPR.mob.<id> = {
  id: 'mob.<id>', name: '한글 이름', w, h, ax, ay,
  clips: { idle: 4, walk: 8, attack: 6, hurt: 3, die: 6 },   // 최소 장수, 더 많아도 된다
  hit: 0.6,            // attack 동작에서 실제로 때리는 순간 (0..1)
  flying: false,       // 나는 몬스터면 true
  palettes: [{...}, {...}, {...}],   // 3개 이상: 기본, 변종, 강한 개체
  draw(b, clip, i, n, pal, ctx) {}, pose(clip, i, n) {},
};
```

- 몬스터는 **왼쪽(주인공 쪽)을 본다.** 공격은 오른쪽으로 예비 동작 -> 왼쪽으로 때리기.
- 나는 몬스터는 몸을 땅 위 8~14점 높이에 그리고, 모든 프레임에 땅(기준점 높이)에 반투명 그림자 타원(`{ shade: false, alpha: 0.35 }`)을 그린다. 기준점은 땅에 둔다.
- die 는 쓰러지거나 부서지거나 연기처럼 사라진다. 마지막 장은 거의 사라진 모습이 좋다 (완전히 비어 있으면 정의에 `allowEmpty: ['die']`).
- hurt 는 맞아서 뒤로 밀리는 반동 (눈을 질끈 감는 등).
- 이름과 성격이 한눈에 보이게. 같은 종의 색 변종은 palettes 로.

### 던질 것 (G, H): `js/spr_items_a.js` (1~10단계), `js/spr_items_b.js` (11~20단계)

```js
TG.SPR.item.t3 = { id: 'item.t3', tier: 3, w: 20, h: 20, ax: 10, ay: 10, clips: { icon: 1, shine: 6 }, draw(b, clip, i, n) {} };
```

- 이름과 설명은 `js/items.js` 에 있다 (고치지 않는다). 단계가 오를수록 일상 물건 -> 무기 -> 원소와 마법 -> 우주로 간다. **높은 단계일수록 더 화려하고 신기해 보여야 한다** (빛, 오라, 이펙트 색). 합칠 때 "다음은 뭐가 나올까" 하는 기대가 핵심이다.
- `icon`: 보드 칸에 놓이는 정지 그림. 20 x 20 칸을 거의 채운다 (외곽선 포함 가장자리 1점은 비운다). 던질 때는 화면이 이 그림을 돌리면서 날린다.
- `shine`: 보드에서 반복되는 6장 (반짝임이 훑고 지나감, 불꽃 일렁임, 별 깜빡임 등). icon 과 같은 물건에 작은 움직임만 더한다.
- 작은 크기라서 실루엣이 한눈에 읽혀야 한다. 비스듬히(대각선) 놓으면 길쭉한 물건이 크게 보인다.
- 담당 G: 1 연필, 2 젓가락, 3 포크, 4 가위, 5 깡통, 6 프라이팬, 7 벽돌, 8 부메랑, 9 손도끼, 10 볼링공
- 담당 H: 11 번개, 12 불덩이, 13 얼음창, 14 수정구, 15 마법책, 16 용의 이빨, 17 별똥별, 18 행성, 19 태양, 20 블랙홀

### 배경 (I): `js/spr_bg.js`

```js
TG.SPR.bg.<theme> = { id: 'bg.<theme>', name, w: 200, h: 120, ax: 0, ay: 0, tile: true, outline: null, shade: false,
  clips: { sky: 1, far: 1, near: 1, anim: 6 }, palettes: [{...}], draw(b, clip, i, n, pal) {} };
```

- `sky`: 맨 뒤 하늘 (빈틈없이 칠한다. 색 띠와 점묘(디더링)로 그라데이션, 해/달/별/구름).
- `far`: 먼 풍경 실루엣 (산, 나무숲, 동굴 벽...). 위쪽은 투명. 천천히 흘러간다.
- `near`: 땅과 가까운 풍경. 땅 윗면이 y = 100. 그 아래 땅 단면(흙, 돌, 풀)을 120까지 채운다. 빠르게 흘러간다.
- `anim`: 투명한 겹 그림 6장 반복 (반딧불, 낙엽, 불티, 눈송이, 별 반짝임).
- `far`, `near` 는 **가로로 이어 붙여도 이음매가 없어야 한다** (x = 0 과 x = 200 이 이어진다). 주인공이 달리면 배경이 흘러간다.
- 테마 6개: `field` 들판(맑은 낮), `forest` 숲(노을), `cave` 동굴(어둠과 수정 빛), `volcano` 화산(붉은 하늘, 용암 강), `ice` 빙하(오로라 밤), `space` 우주(행성과 성운).
- 몬스터와 주인공이 잘 보이게 배경은 채도와 대비를 조금 낮춘다.

### 이펙트, 숫자 글꼴, UI 아이콘 (J): `js/spr_fx.js`

- `TG.SPR.fx.<name>` (외곽선 없어도 됨, `outline: null` 가능): `hit` 맞는 순간 터짐 5장, `bighit` 큰 터짐 6장 (거대 몬스터), `coin` 동전 튀어오르며 회전 8장, `poof` 몬스터 사라지는 연기 6장, `merge` 합성 순간 고리와 반짝임 8장, `craft` 새 물건이 퐁 나타남 6장, `discover` 새 단계 발견 빛줄기 10장, `levelup` 위로 솟는 반짝임 8장, `throwfx` 던질 때 손에서 나는 바람 4장. 크기는 각자 알맞게 (보드용 merge/craft/discover 는 24 x 24 쯤).
- 숫자 글꼴: 데미지와 골드 표시용 픽셀 글꼴. `TG.SPR.ui.font = { glyphs: { '0': ['01110', ...], ... } }` 처럼 각 글자를 줄 문자열 배열로 정의 (1 = 칠함). 글자: 0~9, `.`, `+`, `-`, `x`, 그리고 큰 수 단위 `만 억 조 경 해 자 양 구 간 정` (높이 7점, 숫자 폭 5점, 한글 폭 7점). 그리고 `TG.pixelText(str, color, outlineColor) -> { w, h, data }` 함수를 만든다 (1점 외곽선 포함, data 는 RGBA Uint8ClampedArray. 브라우저면 `canvas` 도 붙인다: `TG.toCanvas`).
- UI 아이콘 `TG.SPR.ui.<name>` (16 x 16, `clips: { icon: 1 }`): `coin` 골드, `lock` 잠김 칸, `craft` 제작(망치), `autoCraft` 자동 제작(톱니와 손), `autoMerge` 자동 합치기(자석), `atk` 공격력(주먹이나 칼), `hp` 체력(하트), `craftLv` 제작술(모루와 불꽃), `climb` 등반술(깃발 꽂힌 산), `slots` 필드 칸(격자), `dex` 도감(책), `stage` 스테이지(깃발).

## v0.2 추가 작업

v0.1 그림은 다 들어갔다. 실제 게임에서 쓰이는 모습은 `index.html` 을 브라우저(Playwright)로 열어서 볼 수 있다. 도구 쪽 바뀐 점:

- `b.px` 는 이제 배율 S 만큼 크게 찍힌다 (거대 몬스터에서도 점 크기가 같다).
- 외곽선은 불투명한 점 둘레에만 생긴다 (반투명 그림자, 빛에는 안 생긴다). 부품 외곽선 바깥에 겹으로 더 두르지 않아서 늘 1점이다.
- 반투명 부품은 아래 그림과 섞인다.
- 확인용 스크립트는 scratchpad 아래 **자기 담당 이름의 하위 폴더**에 둔다 (다른 담당과 파일이 겹치지 않게).

### 던질 것 21~40단계 (K, L)

형식은 v0.1 의 던질 것과 같다 (`TG.SPR.item.t21` ..., 20 x 20, 기준점 (10, 10), `clips: { icon: 1, shine: 6 }`). 이름과 한 줄 설명은 `js/items.js` 에 있다. 이미 있는 1~20단계(`js/spr_items_a.js`, `js/spr_items_b.js`)를 먼저 보고 **그보다 더 화려하고 신기하게** 그린다. 단계가 오를수록 빛, 오라, 움직이는 이펙트가 커진다. 그래도 작은 칸에서 무슨 물건인지 한눈에 읽혀야 한다.
